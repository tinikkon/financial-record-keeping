# Таблица семейных финансов

Веб-аналог Excel для семейного бюджета: листы-месяцы, произвольные колонки,
формулы и мгновенная синхронизация между устройствами.

## Зачем

Семейный бюджет вёлся в облачной таблице с двух телефонов. У каждого устройства
своя копия файла, копии расходятся, и правка, сделанная одним человеком, могла
не дойти до второго — экран показывал вчерашние цифры при живом интернете.

Приложение решает это тем, что копии нет вовсе: единственная правда лежит в базе,
а экран — её отражение. Правка ячейки появляется на втором устройстве за долю
секунды, а при любом расхождении клиент молча перезагружает лист целиком.

Приложение не знает слов «приход» и «расход» — оно знает листы, ячейки и формулы.
Смысл колонок задаёт пользователь, вписывая заголовки, ровно как в Excel.

## Архитектура

```
        браузер / телефон
               │
            traefik
               │
   ┌───────────┴────────────┐
   │                        │
sheet-service          history-service
(настоящее)              (прошлое)
   │      │                  ▲
   │      └── WebSocket ──►  │
   │                         │
   └──── RabbitMQ ───────────┘
   │
 MongoDB
```

**`sheet-service`** отвечает за настоящее время: пользователи, книги, листы,
ячейки, вычисление формул, рассылка изменений по WebSocket.

**`history-service`** отвечает за прошлое: неизменяемый журнал правок,
состояние листа на любой момент, месячные сводки.

Связь односторонняя — через RabbitMQ. Если сервис истории лежит, таблица работает
как ни в чём не бывало, а журнал догоняет из очереди после подъёма.

Почему граница проведена именно так и какие варианты отвергнуты —
в [`docs/specs/2026-09-18-design.md`](docs/specs/2026-09-18-design.md).

## Что внутри стоит посмотреть

**[Движок формул](packages/formula-engine)** — отдельный пакет без Laravel: лексер,
парсер с приоритетами операций как в Excel, вычислитель, извлечение зависимостей,
планировщик пересчёта с обнаружением колец ссылок. Не знает ни про базу, ни про HTTP —
значения ячеек получает через интерфейс. Деньги считаются точной десятичной
арифметикой: `0.1 + 0.2` здесь равно `0.3`.

**[Применение правок](services/sheet-service/src/Finance/Domains/Calculation/Actions/ApplyCellEditsAction.php)** —
пачка правок в транзакции: формулы разбираются до записи, поэтому одна сломанная
отменяет всю пачку и не затирает прежнее содержимое.

**[Поиск зависимых ячеек](services/sheet-service/src/Finance/Domains/Cells/Repositories/CellRepository.php)** —
запрос к MongoDB с `$elemMatch` по границам диапазонов. Формула `=СУММ(B3:B90)`
хранит не 88 адресов, а одну пару границ.

**[Разбор решений по MongoDB](docs/mongodb.md)** — почему ячейки отдельной коллекцией,
как устроены многоключевые и убирающие по сроку индексы, зачем `Decimal128`
для денег, зачем набор реплик из одного узла и как проверить работу индекса
через `explain`.

## Стек

PHP 8.4, Laravel 13, MongoDB 8, RabbitMQ 4, Laravel Reverb, Pest, PHPStan,
FrankenPHP, Docker. Фронтенд планируется на Vue 3 + TypeScript + Vite.

## Как поднять

Всё работает в контейнерах: локальные версии PHP и Node не используются
и не меняются.

```bash
make init     # файл окружения, ключи подписи токенов, сборка образов, зависимости
make up       # поднять окружение
make indexes  # создать индексы коллекций MongoDB
```

Завести пользователя:

```bash
docker compose exec sheet-app php artisan finance:create-user почта@пример.рф Имя
```

Адреса после запуска: API таблиц `api.finance.localhost:8088`,
история `history.finance.localhost:8088`, панель RabbitMQ `rabbit.finance.localhost:8088`.

## Тесты

```bash
make test           # все наборы
make test-engine    # только движок формул
make test-sheet     # только сервис таблиц
make test-history   # только сервис истории
```

Тесты сервисов ходят в настоящую MongoDB, а не в заглушку: проверяется в том числе
поведение индексов, транзакций и запросов.
